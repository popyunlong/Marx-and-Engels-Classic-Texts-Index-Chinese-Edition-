# Paddle 引文修复运行规程

目标：10 月 5 日前争取完成 166,952 页优先范围；期限不能降低网站可用性、识别质量、定位及回滚门槛。OCR 完成只代表候选材料产生，不代表修复已上线。

## 生产边界

主站代码只经既有 `deploy/release.ps1` 从指定协调者维护的干净、已推送 `production` 发布。新增 `-CorpusArchive` 在同一个 `/run/lock/marx-search-release.lock` 事务内安装不可变语料包，保留旧版本；不覆盖会员、订单、笔记、文库或期刊数据库。回滚仍使用 `deploy/rollback_release.ps1`，同时恢复目标应用绑定的正文、坐标及索引。

先发布兼容基础版本，保留原数据库及其指纹作为回滚基线；修订版通过质量验收并完成回滚演练后才绑定上线。首次修订版回滚到兼容基础版本时，必须验证原数据库仍与其记录的父版本指纹完全一致；后续版本回滚到各自绑定的不可变语料包。没有 `config/corpus_release.json` 时保持既有数据路径。有绑定但数据不匹配时拒绝启动候选，不回退混用旧数据。目录版本独立保留，页面 ID、源文件、物理/印刷页码、目录输入必须完全一致。既有布局引用带指纹校验，旧偏移不可套用新正文；新坐标仅精确匹配，无法确认时不高亮。

## 个人文库节点

工作区 `/home/data/marx-corpus-repair`：`source` 是 root 所有的只读快照，`legacy` 保留核验后的旧材料，`jobs/raw/geometry/candidates/reports/tmp` 分别存放断点、不可覆盖的 API 结果、候选坐标、候选包、验收和临时文件。原始历史目录保留到仓库规定的保留期结束。

修复用户 `marx-paddle-repair` 不持有主站 SSH 密钥、发布权限或业务数据库写权限。凭据仅放 `/etc/marx-paddle-repair.env`（root:root 0600），只包含 Paddle 凭据，不复制主站整个环境文件。服务 `deploy/marx-paddle-repair.service` 依赖数据盘挂载，CPU 2 核、内存软限 2 GiB/硬限 3 GiB，低优先级 I/O，写权限限定作业目录。空间不足 max(15 GiB,20%) 时暂停。

安装包只能从通过检查并已推送的 `main` 构建，使用现有源树清单/归档工具；不得从功能分支、脏工作区或未推送提交部署。`deploy/install_paddle_worker.sh ARCHIVE CHECKED_MAIN_SHA PYTHON EXPECTED_WORKER_ID` 在锁内校验清单，安装 `releases/paddle-<sha>/app` 并记录当前指针；默认不启动、不开自启。初始 `scope.json` 由 root 所有且只读，允许总共 12 页。服务重启不能绕过总量限制。通过 12 页新任务测试后才把范围改为 300 页，扩量前须核实账户总额度、网站预留额度及费用；额外付费必须得到用户确认。

## 快照与任务

读取主站时使用非阻塞共享发布锁、短只读操作和 2 MiB/s 上限，锁忙或线上版本变化就停止。复制前后校验当前发布 ID、目录绑定、源文件大小/时间及 SHA-256；SQLite 完整性验证通过才生成 `source/manifest.json`。快照含正文、现有坐标、主题索引、目录版本及布局索引；处理页所属 PDF 也必须有 SHA-256 和原始 `stat`。不得使用历史旧语料继续发布。

运行入口：

```sh
python scripts/paddle_corpus_repair.py plan --root /home/data/marx-corpus-repair --per-group 100
python scripts/paddle_corpus_repair.py status --root /home/data/marx-corpus-repair
```

先从《文集》1、《毛选》1、《邓选》3、《习近平著作选读》上、《治国理政》5 选页，A/B/C 交替执行，前 12 页每组 4 页；300 页试点每组 100 页。全量计划不传 `--per-group`，先五册再按三类逐册轮转。同组优先已报告错误较多的册，再优先缺失坐标比例高的册。报错聚合从只读导出填入 `source/priority-hints.json`（源文件对应非负整数 `reported_errors`，不含用户身份或反馈正文）；缺失比例从坐标快照计算。聚合文件哈希固定在任务库，变化后新建队列。斯大林、年谱和中央文献、其他学术资料不进入该优先任务队列。全量启动前核对书名、页数和报错聚合，不凭标题猜页数。

每次运行先收集至少 30 分钟基线，每 30 秒监测。关键探测连续两次失败，或两个连续五分钟窗口 p95 同时超过基线 20% 与 200 毫秒，停止新增提交并保存已接受任务结果。基础探测覆盖运行状态、首页和登录入口；它不能替代下述全功能验收。`PAUSE` 文件或停止信号也会停止新增请求，包括行坐标的第二次请求。挂载、资源和版本异常禁止继续。

重启可通过 `--baseline-file` 复用 `source` 内 root 所有且无写权限的观察证明，避免重复等待。证明包含完整 30 分钟样本、采集端 `observed_at` 和原始基线；最后观察距启动少于 10 分钟、采样间隔不超过 60 秒，线上版本和目录一致，延迟仍满足原阈值。服务器时钟仅作诊断，不能拿另一台机器的时钟判断采集记录新鲜度。复用后仍先检查当前网站，并沿用原始停止阈值持续监测，不能通过复用放宽门槛。运行入口使用可执行包装器调用虚拟环境真实入口，安装后由修复用户核验 PDF 组件导入。

延迟基线与持续观察必须来自同一测量位置。本机基线不能与文库节点访问公网的往返时间直接比较。使用主站本机基线时，操作者每 30 秒只读测量主站并原子写入 root 所有、不可写的 `source/health-live.json`；工作程序通过 `--health-observation-file` 验证原始基线哈希、测量来源和线上版本后使用这些样本。证明超过 75 秒、观察器退出或内容异常立即停止新增作业。修复用户只读取观察证明，不获得主站密钥。公网探测仍用于启动时验证站点可达及版本一致。

每页先持久化请求指纹和配额占用，再提交 Paddle；远端任务 ID 立即落库。请求结果未知或提交中断时进入 `uncertain`，必须核对远端记录，不能重新上传。所有队列共享同一账户配额账本。模型、输入 PDF/图像、旧正文、参数、原始 JSON 哈希共同记录。未对齐、空白页、异常坐标及高风险差异均隔离等待复核。原生字符坐标和行级 OCR 分别保存，段落框不能冒充行框；没有字符证据时只能整行高亮。

后续提交携带 `batchId=marx-<已持久化的请求指纹>`，响应丢失时通过官方批次查询只读核对任务 ID。批次标识不保证请求幂等；空列表、查询失败或多个结果均不能作为重新提交依据。2026-10-01 首次测试中未携带批次标识的历史不确定请求必须单独核查，不能把新标识追溯套用给旧请求。

用户明确授权后，可把该次无法查询的历史请求永久隔离，继续其他页。授权保存为 root 所有、不可写的 `source/uncertain-quarantine.json`，绑定核心清单哈希、原请求指纹、页面、模型、旧正文及 PDF 哈希，记录用户指令和隔离原因。原任务保持 `uncertain`，配额占用保留，该页所有模型和图像都不得再次提交。检查覆盖节点全部任务库；其他不确定请求仍阻止新增作业。12 页范围在排除该页后固定，补入下一优先页，重启不能不断追加页数。此例外不解除网站健康、资源、费用或上线门槛，隔离页永远不计入已完成覆盖率。

## 复核、候选和上线

`review` 入口要求逐页提供 reviewer、decision、reason、原书已核对证明、旧正文及结果哈希。新结果不能因为更新就自动接受。数字、姓名、否定词、脚注、显著增删都应列入原书对照；当前实现把所有变化都保留为人工复核项。

`scripts/build_paddle_candidate.py build --root ... --version ...` 仅修改新建候选数据库中已接受页面的正文与规范化文字，并生成同版坐标及布局索引，保留其他页面和主题索引。失败目录保留诊断，不能产生可发布清单。`seal` 要求真实质量报告，报告必须绑定候选 ID 和正文/坐标/布局 SHA-256；不得复用另一版本的报告。封存包经 `scripts/corpus_deploy.py pack` 生成归档。

补齐目录与布局快照时，另写只读 `source/auxiliary-manifest.json`，绑定原始核心清单哈希、线上版本、目录版本及全部布局文件哈希，不修改已绑定任务库的核心清单。候选构建在创建输出目录之前核验正文、坐标、主题索引和全部辅助文件；辅助清单缺失、跨版本或校验失败时拒绝构建。

质量门槛：原书验证至少 20,000 字、CER ≤ 0.3%、已知错误减少至少 50%、高质量旧页不退步、全部高风险差异复核、每个变更册至少 10 页、定位样例至少 150 个、准确率 ≥ 99%、错书错页为零。

网站验收记录必须绑定候选应用和语料版本，逐项通过精确/模糊/组合/单书检索、分页排序、复制/引用/导出、PDF/目录/跳页/页内查找/高亮/旧链接、AI 问答/流式输出/来源、书签/笔记、登录/会员/个人文库/各库入口/期刊任务。Chrome、Edge、移动端实际验收及回滚演练均通过后，才允许发送候选放行回执。支付、邮件及用户写入只在隔离环境测试。

首批切流后观察 30 分钟及 24 小时。任何回归停止扩量并按既有事务回退，期间新增用户数据不随语料回退。约 50,000 页/日的目标必须由试点实测和获准额度支持；未取得额度、质量或完整验收证据时如实记录未完成项，不以赶工绕过门槛。
