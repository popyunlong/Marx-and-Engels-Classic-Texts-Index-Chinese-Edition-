# 国内外研究动态：候选版本与发布交接

## 范围

新入口 `/research-updates`，后台 `/admin/research-updates`。期名“本周国内外研究动态”。旧 `/journal-alerts/latest`、双语全文、样刊、订阅确认和退订链接继续使用。

`research_updates.py` 在既有期刊数据盘的 SQLite 中仅增加 `research_*` 表，不重建或覆盖旧表。复用 `journal_alerts` 会员资格、订阅、SMTP 和 AI 配置。采集不下载 PDF，不依赖全文翻译，不限制每期 45 篇。

资料路径及密钥不得提交到 Git。候选资料在本机独立数据库中整理，**不得将候选数据库覆盖生产期刊库**。

## 运行与审核

- 周六北京时间 22:00 建立截至该时刻的七天草稿；区间左闭右开。日期只有年月且与采集区间重叠、周界日期缺少时刻或无法解析时，进入日期待核对区；明显早于该周的年月归入历史资料，首补采忽略。官网在线日期与正式刊期分开保存。
- `marx-search-research-collect.timer` 只建立采集任务；工作计时器每两分钟消费采集／翻译队列；投递计时器每两分钟消费已经人工发布的邮件队列。上期未发布不阻塞下期。
- 采集配置取既有 45 刊名单，官网入口集中在 `research_collect.PUBLISHERS`。Crossref 按索引时间增量同步并保存分页检查点；首采按发表日期限定。电子 ISSN 会继续尝试，即使纸刊 ISSN 返回 404。官方目录、RSS 和在线优先链接用于补充；OpenAlex 预测关键词仅保留作索引资料，不作为原刊关键词。
- 来源报告区分新增、检查无新增、部分失败与失败。403、429、解析不到目录均不算“无新文”。出版社动态页面或访问验证可能导致不完整，发布前须查看逐刊报告。
- 第一次建立基线忽略历史目录；基线之后发现的早期文章归入补录。同 DOI 或能可靠匹配的在线优先记录补齐刊期时更新原记录，已发布内容进入更正草稿。仅索引时间变化不触发更正。
- 译文按原题名、摘要、关键词的散列缓存，最多两个请求并行；复用当前已配置的 AI 通道。原文字段变动使相应译文失效。摘要、关键词缺失时保持空白。
- 后台逐条编辑或按刊确认，支持排除、移入指定周报及人工合并 OCR 修订。日期归属、缺失的外文译名／摘要译文须先处理。缺少原刊摘要、关键词、完整页码本身不阻止确认。
- 所有待复核条目确认或排除后，分别检查网页、邮件预览，再确认发布。发布比较预览散列，在同一事务内保存快照并建立“期次＋收件人”唯一投递。
- 每封邮件发送前重新检查退订和会员资格。明确失败可单封重试；连接中断、超时或发送进程失联记为结果不明，需人工核查。网页不因邮件失败撤回。更正只更新网页，不重发整期邮件。

## 国内自动推送

本机脚本 `scripts/research_domestic_sync.py` 只读取 `D:\CodexData\outputs\journal-monitor` 下直接子目录的 `catalogue.md` 和可选 `metadata.json`；跳过历史、链接、正在写入和非目录文件。Markdown 按现有格式解析；结构化资料为 `source`、`papers`、`warnings`、`needs_review`，差异保留为核对提示。源文件不改写。

后台先生成可撤销的“仅导入凭据”。上线成功后在本机执行 `deploy/install_research_sync.ps1 -RunOnce`，在安全输入框粘贴凭据。默认每 15 分钟和登录后运行，使用已有 Python 3.10。状态和用户级 DPAPI 加密凭据位于 `D:\CodexData\data\research-sync`。凭据不进命令行、Git 或日志。未取得服务器导入凭据前不安装空任务。

接口 `POST /api/research-updates/imports` 使用 `Authorization: Bearer …`，只接受草稿导入。JSON 字段为：

| 字段 | 约定 |
|---|---|
| `version` | `1` |
| `source_id` | 同一国内目录各版本的稳定标识 |
| `markdown` | 原始 Markdown，最多 2 MB |
| `metadata` | 配套 JSON 对象；缺少时为 `null` |
| `content_hash` | 对 `{markdown, metadata}` 用 UTF-8、键排序、无空白、保留中文序列化后的 SHA-256；直接复用脚本生成 |

返回导入编号、解析数量、重复项、冲突、待复核数和期次。相同来源与散列重复提交返回原结果。断网或响应不明时下轮重试；服务端幂等保护防止重复。后台导入记录可以查看原始 Markdown 与完整证据。修订文件有独立导入版本，已发布快照不被覆盖。

## 首期草稿交接

首期截止 `2026-10-03T22:00:00+08:00`，开始 `2026-09-26T22:00:00+08:00`。

1. 用候选库环境运行 `python scripts/research_candidate.py export <草稿文件.json> --issue 1`。文件仅含题录、国内原稿和逐刊报告，不含订阅者、凭据、批准状态或邮件队列。
2. 新版本正式上线后，将文件传到生产共享数据目录。由协调者在规定发布锁 `/run/lock/marx-search-release.lock` 下，以应用身份和既有服务环境执行 `python scripts/research_candidate.py import <草稿文件.json>`。使用 `flock -n` 包住整个操作，避免和发布事务并行；不要在已持有锁的事务内再次获取锁。
3. 导入会在生产期刊库兼容性新增草稿，保留国内版本关系；重放幂等，所有条目仍待复核。若目标期次已发布则拒绝整包导入，改走后台更正流程。
4. 查看实际覆盖报告，重试失败期刊；校订日期、作者、文章类型、OCR 疑点和译文。完成预览之后由人工发布。

也可在新版本服务环境直接运行 `python scripts/research_update_worker.py --stage collect --end 2026-10-03T22:00:00+08:00 --backfill` 重建首期。后台支持指定周次及单刊重试。

## 发布与回退

从当前 `main` 创建的独立候选分支经快速门禁、全量测试、页面检查后合入 `main`。合并后的 CI 集成和发布门禁仍须成功。协调者发布前重新核对 `/api/runtime`、远端主线及实际生产版本。

只允许从干净、已推送且 HEAD 等于 `origin/production` 的 `production` 分支运行 `deploy/release.ps1 -ExpectedLive <实际版本>`；本功能不改变发布锁、不可变版本目录、流量切换和健康检查流程。

发布事务先记录六个新旧计时器的启用／运行状态，再暂停旧采集、全文处理、发送及新工作任务。健康检查完成后停用三个旧计时器，启用三个新计时器。`research-timers-before.tsv` 用于失败恢复；首次切换前的 `research-legacy-timers.tsv` 随后续版本保留，保证跨多个新版本回退到旧版时仍能恢复原计时器状态。

回退使用 `deploy/rollback_release.ps1`，明确当前版本与目标版本，仍由既有事务持有发布锁。目标旧版本没有研究动态单元时允许缺失这些新增单元，停止新计时器并恢复首次切换前的旧计时器状态；不删除 `research_*` 数据。回退期间本机推送可能收到 404，脚本不登记成功，上线恢复后继续重试。

## 内容规则筛选与读者展示（2026-10-04）

统一规则位于 `research_content.py`，用于国内 JSON／Markdown 导入、外文索引与出版社采集、后台重新筛选和发布检查。每条保存规则版本、判断、原因和题名／栏目证据。明确的封面、目录、刊务、投稿／订阅说明、广告、征稿、新书推广与活动通知自动排除；党员／读者来信栏目及国家统计局署名的“统计图表：”条目也排除。缺摘要、缺作者、无 DOI、只有起始页均不作为排除条件。书评、编者按、评论、访谈、学术通信及更正保留，并据原刊栏目、明确题名或署名纠正类型。模糊的报道、转载、资料栏目进入后台内容复核，避免凭题名印象删除学术论文。

出版社解析保存明确的目录栏目和文章类型；例如 Book Reviews 与 Discussion 用于书评／评论分类。纯刊务目录可以记录为已检查并列出过滤记录；无法识别目录仍是来源失败。采集报告保存过滤题名、来源和规则，便于区分无新学术内容与采集失败。

后台“按规则筛选本期条目”保留既有排除、原稿、条目编号与目录序号；排除条目仍作相邻页码的目录锚点。重新推断页码不会恢复排除项。人工恢复规则排除项或确认模糊内容须填写原刊依据，记录操作人；仅导入凭据不能提交此依据。发布时再次检查规则，防止旧审批绕过新筛选；已发布快照只能走更正流程，不被批量筛选改写。

## 刊名与目录折叠（2026-10-04）

`research_journals.py` 为现有45种外刊提供统一中文译名，保留原刊名称；适用于刊期标题、期刊索引、筛选、题录说明和邮件。原刊名仍用于来源匹配与引文导出，兼容 Noûs/Nous、&/and 等名称写法。
