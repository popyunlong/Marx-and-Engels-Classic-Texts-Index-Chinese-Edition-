## 一、目标

在首页提供**两个入口选项**：

1. **阅读学习界面**：点进去就是现在的全部功能模块（引文检索、篇章直达、全文阅读 / 大辞典 / AI 导学 / 期刊 / 流式阅读等卡片、公告、注册分布等）。
2. **AI 对话界面**：把现在的「AI 随心问」单独拉成一个页面，并把「研究型检索」的能力也并进来，合成**一个研究导向、可连续问答、带上下文的大 AI 问答页**。

## 二、现状梳理（已核对代码）

### 2.1 首页 `/`（`templates/index.html`，5358 行）
- 顶栏（登录/注册/会员套餐/账户/管理后台）→ hero（三人油画背景 + 收录文献标签）→ 会员状态条 → 继续阅读条 → 两栏 grid：
  - **左栏**：引文检索面板（含 3 个模式标签页）、检索结果框、篇章直达、首页功能卡（全文阅读 / 大辞典 / AI 导学 / 期刊 / 流式阅读，顺序由控制台 `index_card_order` 驱动）。
  - **右栏**：公告、注册用户分布、社区、留言反馈。
- 底部：**「AI 随心问」右侧抽屉**（`_ai_assistant.html`，默认 drawer 形态；`ai_assistant_mode=='card'` 时改为右栏内嵌卡片）+ 马克思宠物。

### 2.2 引文检索面板 = 三个模式标签（关键）
`templates/index.html:2304`：
- `standard`（精确/模糊检索）— 走 `/api/search`。
- `associative`（联想检索）— 走 `/api/search/associative`，意图 locate/auto。
- `research`（**研究型检索**）— 同 `/api/search/associative`，`mode=research`。

### 2.3 「研究型检索」当前行为（`app.py:12365` `api_search_associative`）
- **一次性**（非对话）：输入一个命题 → AI 扩展线索 → 在真实语料接地定位 → `generate_research_review` 产出**约 5000 字综述 + 20–24 条 [N] 引用卡**（引文不可伪造，全部来自真实命中）。
- 计量：需 `research` 权限位 + **每周「次数」额度**（登录 5 / 月 15 / 季 20 / 年 25，`research_review` feature）+ 研究资源包次数兜底。
- 前端渲染在 `.assoc-results.research`（黑玻璃/暖羊皮纸双主题）。
- **没有多轮上下文**——每次都是独立命题。

### 2.4 「AI 随心问」当前行为（`app.py:11859` `/api/ai/search-chat` + `static/ai-assistant/`）
- **多轮对话**：前端带 `messages` 历史，SSE 心跳保活。
- continuous 线程存 `marx-ai-thread-v1`（跨页、跨标签持续；抽屉、阅读器 AI 导读共用同一条会话）。
- 三个开关：模型通道（DeepSeek / 智谱 GLM 联网）、「检索引文库作答」接地开关、检索范围 chips（著作群）。
- 计量：`search_chat` 权限位 + **每周 token 额度**（`chat` credit）+ 资源包。
- 组件自包含（命名空间 `aia*`），已全站复用（viewer 除外）。

### 2.5 两者的根本差异（合并的难点）
| | AI 随心问 | 研究型检索 |
|---|---|---|
| 交互 | 多轮、连续上下文 | 一次性、无上下文 |
| 产物 | Markdown 回答 + 引文 | 5000 字综述 + 20–24 引用卡 |
| 计量 | 每周 token 额度（chat） | 每周次数额度（research） |
| 权限位 | `search_chat` | `research` |
| 后端 | `/api/ai/search-chat` | `/api/search/associative?mode=research` |

**合并成「可连续问答的研究导向页」= 让研究级的深度产物也进入一条连续会话线程**，这是本次的核心设计点，需站长在下面几个方案里选。

### 2.6 部署与协作约束（务必遵守）
- **范围化部署**：`update_cloud.ps1` 临时改清单只推改动文件；新静态文件须加 `deploy/cloud_patch_files.txt`。
- **预览优先**：本地 Flask + 应用内浏览器跑通并让站长确认后，再部署。

## 三、设计方案（含推荐，具体取舍见第四节）

### 3.1 首页双入口
推荐：**保留 `/` 为完整阅读学习首页**，在 hero 正下方加一个醒目的**双卡切换区**：
- 卡 A「阅读学习」——默认，即当前首页（原地，不跳转或锚点定位到功能区）。
- 卡 B「AI 研究对话」——跳转到新页 `/ai`。

（另一可选：`/` 改为极简「二选一」闪屏，原首页迁到 `/study` 之类新路由。见第四节 Q1。）

### 3.2 新 AI 对话页 `/ai`（新增路由 + 模板）
- 全屏、聊天式布局，复用现有 `aia*` 组件的对话/Markdown/引文渲染逻辑（避免重写）。
- **一条连续会话线程**（复用/扩展 `marx-ai-thread-v1`），支持连续追问、带上下文。
- 顶部保留：模型通道、接地开关、检索范围 chips（沿用随心问那套，localStorage 记忆键复用）。
- **深度选择（研究导向的关键）**：每条提问可选「快速问答」或「研究综述」两档（见 Q2）：
  - 快速档 → 走 `/api/ai/search-chat`（现有多轮逻辑），消耗 chat token 额度。
  - 研究档 → 走研究综述生成（复用 `generate_research_review` 管线），产出综述 + 引用卡**内联进会话气泡**，消耗 research 次数额度。
- 两种额度条都在页面上显示（token 剩余 + 研究次数剩余）。

### 3.3 首页搜索面板的调整
- 把 `research` 标签从首页三标签里**移除**（研究能力搬到 `/ai`），首页搜索面板回到两标签：精确/模糊 + 联想（见 Q3 决定联想是否也一起搬）。
- 「研究型检索」相关的 site_text、额度徽章在首页对应收起。

### 3.4 「AI 随心问」抽屉的去留
推荐：**其他内容页（阅读器等）继续保留右侧抽屉做快捷问答**；首页的 AI 主入口改为跳 `/ai` 全页。抽屉与全页共用同一条 `marx-ai-thread-v1` 线程，体验连贯（见 Q4）。
