# 会员权限、文案与后台性能

基线：`b68b786776ad670c46fa9df9963fffe09f0b56c9`，规划及实施开始时线上、远端 main、production 一致。
工作树：`D:/CodexData/workspaces/membership-admin-20261115`；分支：`codex/membership-admin-20261115`。

## 原因与行为

- 新 20 元 Plus 复用了原 25 元 Plus 的 Pro 模型策略。用户确认新旧 Plus 一律仅提供 Flash 非思考，Pro/Max 保留思考档位；独立研究资源包继续使用自己的 Flash 思考额度。API/MCP 数据资格、排队优先级、售价及钱包金额不变。
- 原会员卡片文案被 `public_plan` 强制覆盖，六条黄框说明为代码常量。现使用 `pricing.plan.*`、`pricing.notice.*` 命名字段，默认值保留当前展示，管理员可在会员页面分组编辑、预览和恢复；原运营文案保存改为局部合并。
- 线上历史日志有 23.284 秒和 22.127 秒的后台响应。原公共上下文每个栏目都加载统计、用户、期刊和邮件预览，并默认循环 30 天完整仪表盘。现各栏目只加载自身数据；总览先返回页面，再独立加载摘要，榜单、阅读异常及历史按需加载。用户分页并批量读取会员快照，运营文案每页最多 40 项。
- 历史主要统计按范围聚合；完整 Excel 保留原列与高用量用户明细，阅读异常详情仅在请求该栏目或完整导出时计算。使用 Server-Timing 和日志记录耗时及 SQL 条数，不记录 SQL 文本或个人数据。

## 设置与兼容

- `unified_settings.ai_model_policies_v1` 保存模型覆盖及单调版本。模型编辑使用版本检查；配置改动影响已有钱包的后续请求。鉴权、预占、恢复和可负担输出计算读取同一策略，关键检查直接读库，绕过进程 TTL。已执行的供应商调用继续正常结算。
- 重用未完成请求时逐一校验实际扣款钱包；另购资源包不能放行仍扣已撤销 Plus 权限的旧预占。重新请求按当前权限选择资源包。
- 套餐与钱包原模型快照不再在启动时被批量覆盖。有效权限通过新版读取规则解释；新旧程序可并行候选运行，不因新版启动提前收紧旧版权限。
- 文案复用 `site_texts`，按提交字段原子合并。会员编辑检查当前值，避免旧标签页覆盖新修改；浏览器 CRLF 和服务端 LF 在比较及保存时统一。
- 新接口：`POST /admin/model-policies`、`POST /admin/membership-copy`、`GET /admin/overview/data?section=summary|tokens|readers|history`。沿用管理员、IP 白名单、二次认证及写入 CSRF 校验。预览仅渲染，不保存。
- 新增 `site_activity(session_key,user_id) WHERE user_id IS NOT NULL` 索引以支持近期在线身份查询。生产启动可幂等增加索引；没有重写账本、压缩数据库或清理业务记录。
- 旧版回滚不能解释新版模型设置，并会恢复旧 Plus Pro 权限；回滚评审必须明确该行为。新版保存的文案和设置无需在回滚时删除。
