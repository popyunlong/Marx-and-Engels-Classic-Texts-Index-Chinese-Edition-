# 首页检索导出一致性修复

基线：`6ead2b5737eabad6b34ce373fe2eb1a145a38894`。实施前重新获取远端并只读核对线上，`main`、`production` 和生产发布均为该提交。工作树位于 `D:/CodexData/workspaces/search-export-consistency-20261107`，分支为 `codex/search-export-consistency-20261107`。本次没有发布或运行生产导出任务。

## 问题证据与边界

原提示“检索数据在导出期间发生变化，任务将重新核对”来自 `emitted != count`，并没有检查语料版本是否变化。两次尝试用尽后，任务状态已经变为 failed，但提示仍承诺重试。

最新基线有两条确定的静态差异：

- 页面聚合与篇章明细过滤跨篇章的排版补充命中；导出收集没有相同过滤。例如两个篇章分别为“甲注”和“乙”，投影产生“甲乙”补充命中：聚合不计，原导出却收集。
- 篇章明细按起点去重，聚合累计普通与补充计数，导出使用保留重复的堆合并。例如“甲乙乙”中普通命中起点 0，删除中间字符的投影也形成起点 0 的“甲乙”：页面明细只有一条，原计数和导出可能累计两条。

只读脱敏统计发现 8 条同类历史任务：精确检索、两次尝试，Word 7 条、HTML 1 条，均已过期。具体任务内容读取曾被自动审批拒绝，未执行；没有读取检索词、范围或用户标识。用户暂不记得原检索条件，因此不能声称已复现截图对应的具体任务。

## 实现

- 排版补充命中统一按物理连续性、完整篇章区间过滤，按来源内的起点去重，与普通命中冲突时保留补充命中的展示。聚合、篇章详情和导出遵循同一规则，合法重叠命中不丢失。
- 导出计数直接累计轻量偏移，不调用引文生成，也不必完成全库聚合后才检查账号上限；保留 1000/5000 条限制、1000 条以内单文件、其余每分册最多 500 条。
- 一轮任务固定范围及公共/个人语料对象。个人文库通过书目版本摘要检测变化，不把缓存淘汰重建误认作数据变更；原有归属检查继续执行。
- 条数不一致保留一次自动重核机会；第二次失败明确结束。真正的来源或模板变更直接要求重建任务。诊断写入现有 manifest，包含阶段、次数、预期与实际条数、版本，不保存引文正文。
- 分册复用绑定任务、算法版本、命中内容和元数据摘要，并核对文件 SHA-256。最终产物保存核验条数和文件摘要；下载拒绝大小或内容不符的产物。
- 内容版本升级为 `exact-consistency-v3`，同时进入 worker 模板签名。新 worker 在领取事务中终止同语料版本下不兼容的旧排队任务，保留失败记录；不抢占仍持有租约的运行任务。兼容历史语料代际的领取路径也执行相同处理。

无需数据库列迁移。现有状态接口增加 `error_code`、`attempts`、`max_attempts`、`retryable`；错误代码包括 `count_mismatch` 和 `source_changed`。前端兼容旧响应，并把旧 failed 记录的“将重新核对”提示改成真实的终止说明。
