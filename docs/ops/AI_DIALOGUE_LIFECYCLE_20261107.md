## 修复行为

三模式的云端同步和本地数据库读取在异步结果返回时核对生成状态、会话身份和请求代次；生成中保留当前消息对象。停止后的旧请求不能清除新请求状态。已核验检查点按稳定消息 ID 和递增版本保存，旧副本不能回滚正文。跨标签页删除不恢复原会话：正在显示的已有回答另存为新的本机恢复副本。

SSE 支持 CRLF 和跨块事件，收到 done 即完成，不等待连接 EOF。静默 30 秒提示、90 秒取消；不会自动重新提交。心跳仅更新状态区，异常通过 finally 恢复按钮。显式续接复用原回答气泡，服务端拒绝并发重复续接，完成结果复用前仍检查范围。

综合生成按明确结束原因完成章节。自然 stop 不要求内部标记；只有 length 自动承接一次，未知 EOF 和再次截断保留 partial。私有完成标记支持跨块，不在代码/引文中解释，标记后文本不发布。标记内部异常插入段落换行也不会泄露。明确重复的较长叙述段落停止追加；引文和短语不按简单重合度删改。

复杂任务只检查原要求，以稳定要求 ID 给出已有覆盖、明确遗漏和新增目标。最多一轮自动补写，草稿先缓冲，通过一次最终检查判定为实质新增的段落才核验发布；同义改写、重复结论或不确定内容不发布。用户主动继续可开始新的有界尝试，但保留已接受正文和章节进度。

流式适配器通过可选 meta_out 返回 finish_reason 与用量；保持文本迭代接口。完成标记后最多等待 5 秒用量尾包，取消/截止监测能关闭阻塞连接。保留一次 after 计费事件；缺失用量使用观测字符估算，明确记录 `usage_estimated`，不当作零用量。精确账单取决于供应商是否返回真实 usage。

新增响应字段为可选的 `stop_reason`、`section_progress`、`checkpoint_version`；本地消息增加 `_revision`、`stopReason`，旧记录缺字段按原逻辑兼容。日志记录停止原因、章节与调用次数，不增加完整用户正文日志。
